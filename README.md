# year-countdown-bot

今年の残り日数と割合を、毎日 日本時間 0:03 ごろに Discord へ投稿する GitHub Actions です。X のアカウント @remaining_days と同じ形式の文面を、X を経由せずに自前で計算して投稿します。

```
2026年11月12日になりました。今年は残り50日です。あと13.7%です。
```

残り日数は当日を含めて数えます（年の総日数 − 通算日 + 1）。割合は「残り日数 ÷ 年の総日数」を百分率にし、小数第1位で四捨五入します。うるう年は総日数を 366 日として計算します。日付は実行環境の時刻（UTC）ではなく日本時間で判定します。

大晦日と元日だけは、あいさつを一言添えます。言い回しは `countdown.py` の `NEW_YEARS_EVE_GREETING` と `NEW_YEARS_DAY_GREETING` で変えられます。

```
2026年12月31日になりました。今年は残り1日です。あと0.3%です。今年も一年お疲れさまでした。
2027年1月1日になりました。あけましておめでとうございます。今年は残り365日です。あと100.0%です。
```

## 構成

| ファイル | 役割 |
|---|---|
| `countdown.py` | 日付計算と Discord への投稿。Python 3.10 以上の標準ライブラリだけで動く |
| `tests/test_countdown.py` | 日付計算・投稿判定・設定値の読み取りのテスト |
| `.github/workflows/post.yml` | 毎日の投稿と手動実行 |
| `.github/workflows/test.yml` | push 時にテストを実行する |

## Discord で Webhook を作成する

1. 投稿先のサーバーで、サーバー名のメニューから「サーバー設定」を開きます（サーバーの管理権限か、ウェブフックの管理権限が必要です）。
2. 「連携サービス」を開き、「ウェブフックを作成」または「ウェブフックを確認」から「新しいウェブフック」を押します。
3. 作成されたウェブフックを開き、名前とアイコン、投稿先のチャンネルを設定します。
4. 「ウェブフックURLをコピー」を押して URL を控えます。

この URL を知っていれば誰でもそのチャンネルに投稿できるので、コードや Issue には書かず、次の手順で Secret として登録してください。漏れた場合は、同じ画面でウェブフックを削除して作り直します。

## Secrets と Variables を設定する

GitHub のリポジトリで「Settings」→「Secrets and variables」→「Actions」を開きます。Webhook URL は「Secrets」タブ、それ以外は「Variables」タブに「New repository secret」「New repository variable」から登録します。Variables は未設定なら初期値で動くので、変えたいものだけ登録すれば足ります。

| 名前 | 種類 | 初期値 | 意味 |
|---|---|---|---|
| `DISCORD_WEBHOOK_URL` | Secret | なし（必須） | 投稿先の Webhook URL |
| `POST_MODE` | Variable | `daily` | `daily` は毎日投稿する。`milestones` は残り日数が `MILESTONE_DAYS` に含まれる日だけ投稿する |
| `MILESTONE_DAYS` | Variable | `100,50,30,10,1` | 節目として扱う残り日数のカンマ区切りリスト。`POST_MODE=milestones` のときだけ使う |
| `SILENT` | Variable | `false` | `true` にすると、通知を鳴らさないメッセージ（flags に 4096 を付与）として投稿する |

値が不正なとき（`POST_MODE=weekly` や `MILESTONE_DAYS=100,fifty` など）は、投稿せずにワークフローを失敗させます。設定の誤りに気付けるよう、黙って初期値に戻すことはしません。

## 手動実行で動作を確認する

1. リポジトリの「Actions」タブを開き、左の一覧から「Post remaining days」を選びます。
2. 右上の「Run workflow」を押し、次の 2 項目を入力して実行します。
   - 対象日：`YYYY-MM-DD` 形式（例：`2028-02-29`）。空なら日本時間の今日です。
   - 確認モード：チェックが入っていると Discord には投稿せず、文面をログに表示するだけです。初期状態ではチェックが入っています。
3. 実行結果の「Post to Discord」ステップのログで文面を確認します。

まず確認モードのまま文面を確かめ、次にチェックを外して実行すると、実際にチャンネルへ投稿されることを確かめられます。`POST_MODE=milestones` のときは手動実行にも節目の判定がかかるので、投稿を試すには対象日に節目の日（`2026-11-12` は残り 50 日）を指定してください。

手元で確認する場合は、次のように実行します。

```bash
python countdown.py --date 2026-11-12 --dry-run
```

## スケジュール実行について

### 実行時刻

cron は UTC で指定するため、日本時間 0:03 は `3 15 * * *` になります。0:00 ちょうど（`0 15 * * *`）にしていないのは、毎時 0 分は GitHub Actions が混雑しやすく、実行が大きく遅れるからです。実際に 0:00 で運用した初日は、約 6 時間遅れて 6:07 に投稿されました。分をずらしても遅延がなくなる保証はなく、このリポジトリでは遅延を許容しています。遅れても日付は実行時点の日本時間で判定するので、0:00 を過ぎてから動く限り文面の日付はずれません。

### 60 日で無効化されるのを防ぐ仕組み

パブリックリポジトリのスケジュール実行は、リポジトリに 60 日間動きがないと自動で無効化されます。対策として、スケジュール実行のたびに `keepalive` ジョブが GitHub API でこのワークフローを有効化し直し、無効化までの期間をリセットしています。ダミーのコミットを積む方法と違って履歴が汚れず、外部の Action にも依存しません。使う権限はワークフロー内の `GITHUB_TOKEN` に付与した `actions: write` だけです。

それでも無効化された場合は、GitHub から通知メールが届きます。「Actions」タブで「Post remaining days」を選び、「Enable workflow」を押すと再開できます。

## Webhook URL の扱い

Webhook URL は Secret から環境変数で渡し、スクリプトはログに出しません。投稿に失敗したときも、URL を含みうる例外メッセージは出さず、HTTP ステータスコードか例外の種類だけを出力します。GitHub Actions も Secret の値をログ上で自動的に伏せ字にします。
